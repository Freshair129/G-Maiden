DAY 16: RICE Scoring คืออะไร? ให้คะแนน Priority แบบมีเหตุผล

เวลามี Feature, Requirement หรือ Backlog item หลายอย่าง
ทีมมักเจอคำถามเดิม:

งานไหนควรทำก่อน?
งานไหน impact สูงสุด?
งานไหนใช้ effort คุ้มสุด?
งานไหนข้อมูลยังไม่แน่นพอ?
แล้วเราจะตัดสินใจโดยไม่ใช้ความรู้สึกล้วน ๆ ได้ยังไง?

นี่คือจุดที่ RICE Scoring ช่วยได้

RICE Scoring คืออะไร?

RICE คือ framework สำหรับช่วยจัดลำดับความสำคัญของงานหรือ feature
โดยให้คะแนนจาก 4 ปัจจัย:

R = Reach
I = Impact
C = Confidence
E = Effort

สูตรคือ:

RICE Score = Reach × Impact × Confidence ÷ Effort

คะแนนสูงกว่า หมายถึงงานนั้น “น่าพิจารณาทำก่อน”
เพราะดูแล้วอาจให้ผลลัพธ์คุ้มกว่าเมื่อเทียบกับแรงที่ต้องใช้

1. Reach — กระทบผู้ใช้กี่คน

Reach คือจำนวนคน กลุ่มผู้ใช้ account หรือ transaction ที่จะได้รับผลกระทบจากงานนี้

คำถามที่ควรถาม:

Feature นี้จะกระทบผู้ใช้กี่คน?
กระทบ user หลักหรือ user ส่วนน้อย?
กระทบกี่ทีม กี่สาขา หรือกี่ account?
ในช่วงเวลาที่วัด จะมีคนได้ใช้จริงเท่าไหร่?

ตัวอย่าง:

ถ้า Feature A กระทบผู้ใช้ 5,000 คน
แต่ Feature B กระทบผู้ใช้ 100 คน
Feature A อาจมี Reach สูงกว่า

แต่ Reach สูงอย่างเดียวไม่พอ
ต้องดู Impact และ Effort ด้วย

2. Impact — ถ้าทำแล้วช่วยได้มากแค่ไหน

Impact คือระดับผลลัพธ์หรือคุณค่าที่เกิดขึ้นถ้าทำงานนี้สำเร็จ

คำถามที่ควรถาม:

ช่วยลด pain point ได้มากแค่ไหน?
ช่วยเพิ่ม conversion หรือ revenue ไหม?
ช่วยลด manual work หรือ cost ไหม?
ช่วยลด risk หรือ error ได้ไหม?
ทำแล้ว user experience ดีขึ้นมากแค่ไหน?

ตัวอย่างการให้คะแนนแบบง่าย:

3 = Impact สูงมาก
2 = Impact สูง
1 = Impact ปานกลาง
0.5 = Impact ต่ำ

ทีมสามารถปรับ scale ให้เหมาะกับบริบทของตัวเองได้

3. Confidence — มั่นใจในข้อมูลแค่ไหน

Confidence คือระดับความมั่นใจว่า Reach และ Impact ที่ประเมินไว้ “น่าเชื่อถือแค่ไหน”

คำถามที่ควรถาม:

มี data รองรับไหม?
มี user feedback ไหม?
มี research หรือ evidence ไหม?
เป็นแค่ assumption หรือมีข้อมูลจริง?
ทีมมั่นใจใน impact ที่คาดไว้กี่เปอร์เซ็นต์?

ตัวอย่าง:

100% = มีข้อมูลแน่นมาก
80% = มีข้อมูลพอสมควร
50% = ยังเป็น assumption เยอะ
20% = เดาเป็นหลัก

Confidence สำคัญมาก
เพราะบางงานดูเหมือน impact สูง แต่ข้อมูลยังไม่แน่น
ถ้าให้ confidence สูงเกินจริง ทีมอาจ prioritize ผิด

4. Effort — ใช้แรงแค่ไหน

Effort คือเวลา แรงคน ความซับซ้อน หรือ resource ที่ต้องใช้ในการทำงานนี้

คำถามที่ควรถาม:

ใช้เวลากี่วันหรือกี่สัปดาห์?
ต้องใช้ทีมไหนบ้าง?
ต้องทำ integration ไหม?
มี dependency กับระบบอื่นไหม?
ต้องใช้ QA / UAT / rollout เยอะแค่ไหน?
Technical complexity สูงไหม?

Effort ยิ่งสูง คะแนน RICE ยิ่งลดลง
เพราะสูตรเอา Effort ไปหาร

พูดง่าย ๆ:

งานที่ value สูงและ effort ต่ำ
มักได้คะแนนดี

งานที่ value สูงแต่ effort สูง
อาจยังสำคัญ แต่ต้องพิจารณาแผนให้ดี

ตัวอย่างการคิด RICE แบบง่าย

สมมติมี Feature A:

Reach = 5,000 users
Impact = 2
Confidence = 80% หรือ 0.8
Effort = 4 person-weeks

สูตรคือ:

5,000 × 2 × 0.8 ÷ 4 = 2,000

ดังนั้น RICE Score = 2,000

ถ้า Feature B ได้คะแนน 700
และ Feature C ได้คะแนน 1,200
Feature A อาจน่าพิจารณาก่อน

แต่ต้องจำไว้ว่า RICE เป็น “input” ในการตัดสินใจ
ไม่ใช่คำตอบสุดท้ายเสมอไป

ใช้ RICE ยังไงให้ไม่มั่ว

รวบรวมงานหรือ feature ที่ต้องเทียบกัน
กำหนด scale คะแนนให้ทีมเข้าใจตรงกัน
ให้คะแนน Reach, Impact, Confidence, Effort
คำนวณ RICE Score
เอาคะแนนมาคุยกับทีมและ stakeholder
ใช้ข้อมูลอื่นประกอบ เช่น strategy, risk, dependency, deadline

ข้อผิดพลาดที่เจอบ่อย

1. ใช้ตัวเลขมั่ว ๆ แต่ทำเหมือนแม่นมาก

RICE จะดีขึ้นเมื่อข้อมูลดี
ถ้าข้อมูลยังไม่แน่น ควรสะท้อนด้วย Confidence

2. ให้ Confidence สูงเกินจริง

ถ้ายังไม่มี data หรือ feedback
อย่าให้ confidence สูงมาก
เพราะจะทำให้คะแนนดูดีเกินจริง

3. ใช้ RICE แทนการคุยกับทีม

RICE ช่วยให้คุยง่ายขึ้น
แต่ไม่ควรใช้เป็นเครื่องมือปิดบทสนทนา

4. ไม่ดู Strategy หรือ Dependency

บางงานคะแนนไม่สูง
แต่อาจจำเป็นเพราะเป็น foundation, compliance หรือ dependency ของงานอื่น

5. เทียบงานคนละประเภทแบบไม่ระวัง

เช่น เอา bug critical ไปเทียบกับ feature nice-to-have ตรง ๆ
อาจทำให้ตัดสินใจผิดบริบท

Checklist ก่อนใช้ RICE

ลองเช็กว่า:

เรากำลังเทียบงานประเภทใกล้เคียงกันไหม?
Reach วัดจากอะไร?
Impact ใช้ scale เดียวกันไหม?
Confidence สะท้อนคุณภาพข้อมูลจริงไหม?
Effort ประเมินโดยคนที่เข้าใจงานจริงไหม?
มี risk, dependency หรือ deadline ที่ต้องพิจารณาเพิ่มไหม?
คะแนนที่ได้สมเหตุสมผลกับ strategy ไหม?

สรุปง่าย ๆ

RICE Scoring ช่วยให้ทีมจัด Priority ด้วยเหตุผลมากขึ้น

Reach = กระทบกี่คน
Impact = ช่วยได้มากแค่ไหน
Confidence = มั่นใจแค่ไหน
Effort = ใช้แรงแค่ไหน

จำไว้ว่า:

RICE ไม่ได้ตัดสินใจแทนทีม
แต่ช่วยให้ทีมคุยเรื่อง Priority ได้มีเหตุผลขึ้น
